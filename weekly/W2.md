## Abstract

Week 2 delivered the core deterministic state tracking, graph validation, and topological scheduling engine for the Adaptive Learning and Path-Planning Engine. All active acceptance tests (35 of 35) pass on the local environment. Key deliverables include: (1) an acyclic curriculum graph loader with five topological validation checks; (2) a Bayesian Knowledge Tracing (BKT) learner state model augmented with a Beta-Binomial variance heuristic and a sliding evidence-window gate; (3) a greedy score-per-minute scheduler evaluated against an exact dynamic programming (DP) oracle across a 250-instance benchmark; (4) a multi-day feasibility checker with explicit reason codes; and (5) a structured audit trace schema.

This report provides an honest accounting of Week 2 results and limitations. The greedy planner achieves a mean approximation ratio of 0.9737 across synthetic benchmarks, but has no universal 95% worst-case guarantee: an adversarial knapsack-pathology instance yielded an empirical minimum ratio of 0.2143 (ratio 3/14). The Beta-Binomial variance $\sigma^2$ and sliding window parameters are heuristic confidence proxies rather than empirically calibrated posteriors. All results in Week 2 rely strictly on synthetic curriculum graphs and generated learner states; real-world dataset acquisition (ASSISTments / Junyi) and empirical calibration are deferred to Week 3. Remote continuous integration (CI) and multi-member git contributions remain unverified.

## 1. Week 1 Summary

Week 1 established the foundational architecture and problem formulation for the adaptive learning engine. The system is framed as a constrained optimization problem: generate a sequence of learning tasks over a multi-day horizon that maximizes knowledge gain while respecting prerequisite constraints, daily study budgets, and memory retention dynamics.

The primary architectural choices established in Week 1, along with the specific rationales documented in early Architecture Decision Records (ADRs), were:
1. **Bayesian Knowledge Tracing (BKT) over Deep Knowledge Tracing (DKT) (`decisions/ADR-001-bkt-vs-dkt.md`):** Chosen because BKT provides closed-form, interpretable belief updates ($P(L_t)$), operates reliably in cold-start / sparse-data regimes, requires no GPU infrastructure, and maintains deterministic state transitions.
2. **Computerized Adaptive Testing (CAT / IRT) over Fixed/Random Diagnostics (`decisions/ADR-002-cat-vs-fixed-random-diagnostics.md`):** Chosen because adaptive item selection based on Item Response Theory information functions minimizes diagnostic test length while dynamically estimating learner initial ability $\theta$.
3. **Topological DAG Scheduling over Neural Set-to-Sequence Models (`decisions/ADR-003-dag-scheduling-vs-set-to-sequence.md`):** Chosen because neural sequence models cannot provide hard mathematical guarantees against prerequisite violations, whereas topological sorting over a validated Directed Acyclic Graph (DAG) guarantees zero prerequisite violations with polynomial-time execution.
4. **Half-Life Regression (HLR) for Spaced Repetition (`decisions/ADR-004-hlr-for-spaced-repetition.md`):** Chosen to model memory retention decay using power/exponential laws parameterized by review history features.
5. **Bounded Contextual Bandit Policy (`decisions/ADR-008-bounded-self-learning-policy.md`):** Proposed as an optional, bounded extension to be explored only after establishing and validating a deterministic scheduling baseline.

## 4. How It Was Done

### 4.1 Curriculum Graph Component (`src/curriculum/`)
The graph component loads curriculum structures from YAML configurations into NetworkX directed graphs. The validator executes five sequential checks:
1. Validates node metadata (duration $\ge 1$, difficulty $\in [0, 1]$, concept string).
2. Verifies that all declared prerequisites exist in the node set (rejecting dangling references).
3. Verifies absence of self-loops ($u \to u$).
4. Verifies absence of multi-node cycles via topological sortability (`networkx.is_directed_acyclic_graph`).
5. Evaluates reachability from foundational root concepts.

### 4.2 Learner State & BKT Component (`src/state/learner_state.py`)
State transitions are modeled using standard two-state BKT with parameters loaded from `config/bkt_params.yaml` ($P_{init}=0.10, P_{transit}=0.25, P_{slip}=0.10, P_{guess}=0.20$):
- **Posterior Update:**
  $$P(L_t \mid \text{obs}=1) = \frac{P(L_{t-1})(1 - P_{slip})}{P(L_{t-1})(1 - P_{slip}) + (1 - P_{L_{t-1}})P_{guess}}$$
  $$P(L_t \mid \text{obs}=0) = \frac{P(L_{t-1})P_{slip}}{P(L_{t-1})P_{slip} + (1 - P_{L_{t-1}})(1 - P_{guess})}$$
- **Transition Step:** $P(L_t) = P(L_{t-1}) + (1 - P_{L_{t-1}}) \cdot P_{transit}$
- **Uncertainty Representation:** Modeled as Beta-Binomial variance $\sigma^2 = \frac{p(1-p)}{\kappa + 1}$, where pseudo-count $\kappa = 2.0 + n$ scales with observed interactions $n$.
- **Sliding Evidence Window ($W=4$):** Evaluates the most recent four observations. Requires $\ge 3/4$ correct for `Mastered` and $\ge 3/4$ incorrect for `Weak`.
- **Classification Boundaries:**
  - `Mastered`: $p \ge 0.85, n \ge 3, \sigma^2 \le 0.05,$ and $\ge 3/4$ recent correct.
  - `Weak`: $p < 0.35, n \ge 2, \sigma^2 \le 0.05,$ and $\ge 3/4$ recent incorrect.
  - `Developing`: $0.35 \le p < 0.85$ and $n \ge 1$.
  - `Uncertain`: Default state when observations $n=0$, conflicting recent history, or variance $\sigma^2 > 0.05$.

### 4.3 Feasibility Checker (`src/planning/feasibility.py`)
Evaluates multi-day feasibility against daily budget $B$ and total horizon $D$. Checks include:
1. Single-block constraint: If any task duration $d_i > B$, returns `BLOCK_EXCEEDS_DAILY_BUDGET` with recommendation: *"Raise daily budget to at least $d_i$ minutes"*.
2. Total capacity constraint: If total required duration $\sum d_i > B \cdot D$, returns `CAPACITY_EXCEEDED` with recommendation: *"Extend horizon by $k$ days or raise daily budget"*.

### 4.4 Greedy Planner & Candidate Universe (`src/planning/greedy.py`)
The greedy scheduler constructs daily schedules by:
1. Identifying the candidate universe: all uncompleted curriculum nodes whose direct prerequisites have achieved `Mastered` status.
2. Computing greedy score-per-minute: $\text{SPM}(i) = \frac{\text{PriorityScore}(i)}{\text{duration}(i)}$.
3. Iteratively selecting the highest SPM candidate that fits within the remaining daily budget.

### 4.5 Exact DP Oracle (`src/planning/oracle.py`)
The exact oracle determines optimal single-day subset selection by exhaustive search over precedence-closed subgraphs:
- Enforces hard input size cap: raises `ValueError` if $N > 20$.
- Implements execution timeout (`timeout_seconds=2.0` raising `TimeoutError`).
- Guaranteed optimal benchmark baseline for small activity graphs ($N \le 12$).

### 4.6 Benchmark Engine (`src/planning/benchmark.py`)
Executes 250 synthetic test instances (50 instances per seed across 5 fixed seeds: 7, 17, 27, 37, 47):
- Generates random DAGs ($N \in [8, 12]$, edge probability $0.3$, durations $\in [1, 5]$ min, budgets $\in [5, 10, 15, 20]$ min).
- Computes greedy schedule score, exact oracle score, approximation ratio $\frac{\text{score}_{greedy}}{\text{score}_{oracle}}$, and execution times.
- Writes structured results to `evaluation/results/w2_greedy_vs_oracle.csv` and summary metrics to `evaluation/results/w2_summary.md`.

### 4.7 Audit Trace Schema (`src/audit/trace.py`)
Provides deterministic auditing of every scheduling decision:
- Schema fields: `node_id`, `day`, `concept_state`, `constraints`, `score_terms`, `decision`, `reason_code`, `policy_version`.
- Standardized `ReasonCode` enum: `PREREQUISITE_UNMET`, `BUDGET_EXHAUSTED`, `REVIEW_DUE`, `MASTERY_TARGET`, `REMEDIATION_REQUIRED`, `DIAGNOSTIC_RECOMMENDED`, `NO_ELIGIBLE_TASKS`, `CAPACITY_EXCEEDED`, `BLOCK_EXCEEDS_DAILY_BUDGET`.
- `check_trace()` validates integrity, asserting no duplicate scheduling, valid state references, and non-empty reason codes.

### 5.5 Hand-Derived Counterexample vs. Measured Worst-Case Instance

1. **Hand-Derived Review Counterexample (12 vs. 18):**
   - Constructed analytically during Week 1 review to demonstrate structural suboptimality of score-per-minute heuristics.
   - Setup: Daily budget $B=6$. Candidate $A$ ($\text{dur}=4, \text{score}=12, \text{SPM}=3.0$), Candidate $B$ ($\text{dur}=3, \text{score}=9, \text{SPM}=3.0$), Candidate $C$ ($\text{dur}=3, \text{score}=9, \text{SPM}=3.0$).
   - Greedy picks $A$ (remaining budget = 2); neither $B$ nor $C$ fits. Total greedy score = 12.
   - Optimal subset selects $\{B, C\}$ ($\text{total duration}=6$). Total oracle score = 18.
   - Theoretical Ratio = $12/18 = 0.6667$.

2. **Measured Worst-Case Benchmark Instance (Seed 47, Instance 215):**
   - Instance parameters: Graph with $N=11$ nodes, daily budget $B=5$ minutes.
   - `item_2`: $\text{duration}=1$ min, $\text{priority score}=3.0, \text{SPM}=3.00$.
   - `item_8`: $\text{duration}=5$ min, $\text{priority score}=14.0, \text{SPM}=2.80$.
   - Greedy selection: Greedy picks `item_2` first due to higher SPM ($3.00 > 2.80$). Remaining budget becomes $5 - 1 = 4$ minutes. `item_8` requires 5 minutes and cannot fit. Final greedy score = **3.0**.
   - Oracle selection: Exact DP evaluates all precedence-closed subsets and selects `item_8` alone ($\text{duration}=5 \le 5$). Final oracle score = **14.0**.
   - Measured Worst-Case Ratio: $\frac{3.0}{14.0} = \mathbf{0.2143}$.

## 6. Issues Faced and How They Were Handled

The development of Week 2 encountered several technical issues. They are documented below in chronological order of occurrence.

### (a) Conflicting-Evidence Test Failure and the Zero-Learning Workaround
* **What Happened:** When testing BKT under realistic parameters ($P_{init}=0.10, P_{transit}=0.25, P_{slip}=0.10, P_{guess}=0.20$), alternating observations ($[1, 0, 1, 0]$) drove $p$ down to $0.2606$ at $n=4$, incorrectly triggering the `Weak` state classification despite mixed evidence.
* **How Found:** Unit test failure during initial BKT sequence testing.
* **Flawed Temporary Fix:** A temporary workaround set transition learning to zero ($P_{transit}=0.0, P_{slip}=0.20, P_{guess}=0.20$), forcing $p$ to stay at $0.50$ to pass tests.
* **Audit & Proper Resolution:** An internal audit flagged the zero-learning parameter set as an invalid model. Realistic parameters were restored, and an architectural decision (`docs/decisions/ADR-007-conflict-evidence-gate.md`) introduced a sliding evidence window ($W=4$). Under this gate, `Weak` requires $\ge 3/4$ recent incorrect answers and `Mastered` requires $\ge 3/4$ recent correct answers. Alternating evidence now remains safely in `Developing` indefinitely.
* **Status:** **Resolved.**

### (b) Invalid Oracle Scaling Benchmark Data
* **What Happened:** The oracle scaling report `evaluation/results/w2_oracle_scaling.md` reported flat runtimes ($\approx 0.12$ ms) across $N=8, 12, 16, 20$.
* **How Found:** Code review of the benchmark generator script revealed that instances were created by slicing an 8-node base graph rather than generating authentic random DAGs of size $N$.
* **What Was Done:** Documented the artifact as invalid. Marked oracle scaling re-benchmarking as an explicit Week 3 task.
* **Status:** **Open (scheduled for W3 re-measurement).**

### (c) Loaded Profiles Ineligible for Mastered Classification
* **What Happened:** Initial test runs revealed that learner profiles loaded from YAML (`config/profiles.yaml`) with high ability ($p=0.92, n=6$) classified as `Developing` rather than `Mastered`.
* **How Found:** Profile inspection script output.

Tests were updated to supply explicit history arrays when asserting mastery transitions.
* **Status:** **Resolved.**

1. **Four-Tier State Classification (`src/state/learner_state.py`):** Established discrete state categories (`Uncertain`, `Developing`, `Mastered`, `Weak`) bounded by probability thresholds, interaction counts, and variance limits.

## 8. Limitations and Claim Boundaries

To ensure complete scientific integrity, the explicit boundaries of the Week 2 deliverables are declared:

1. **Synthetic Data Only:** All evaluations, benchmarks, and tests in Week 2 were conducted using synthetically generated DAGs and simulated BKT state sequences. No real learner interaction data (such as ASSISTments or Junyi Academy) has been acquired or evaluated.
2. **Uncalibrated Heuristics:** The Beta-Binomial variance $\sigma^2 = \frac{p(1-p)}{\kappa+1}$ and the $W=4$ sliding window gate are heuristic engineering mechanisms. They have not been empirically calibrated against real student response distributions.
3. **No Universal Greedy Approximation Guarantee:** The greedy score-per-minute heuristic does not possess a universal 95% approximation guarantee. While achieving a $0.9737$ mean ratio on random DAGs, it exhibits knapsack pathologies with measured worst-case performance as low as $0.2143$.
4. **Oracle Scalability Boundary:** The exact DP oracle relies on exhaustive search over precedence-closed subgraphs. It is bounded by a hard cap ($N \le 20$) and a 2.0-second timeout, making it unsuitable for full-curriculum scheduling.
5. **Windows-Only Execution:** All test suites and benchmarks were executed solely on a local Windows host (Python 3.11). Multi-platform compatibility across Linux/macOS remains unverified in CI.
6. **Remote CI Status Unverified:** Remote GitHub Actions CI execution has not been verified due to absence of public run logs.
7. **Deterministic Duration Proxy:** Task durations are treated as fixed constants. Real-world variance in student completion time is not modeled.
8. **Explicit "Do Not Claim" List:**
   - Do NOT claim that BKT parameters are fitted to empirical student logs.
   - Do NOT claim a theoretical 95% worst-case bound for the greedy scheduler.
   - Do NOT claim that the oracle scales beyond $N=20$.
   - Do NOT claim that Spaced Repetition (HLR) or Contextual Bandits are implemented in code.
   - Do NOT claim that remote CI is passing without verified run links.
