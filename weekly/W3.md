## Abstract

Week 3 resolved all ten technical and architectural defects identified during the mid-review audit, re-ran the full 250-instance benchmark suite with verified order-invariance, established strict configuration provenance, implemented an event-driven dynamic replanning engine, and created a transparent synthetic learner simulator with verifiable latent state isolation. The automated test suite expanded from 35 tests in Week 2 to 93 passing tests and 9 intentional milestone stubs, verified clean from a fresh clone using an automated audit script (`scripts/clean_run.ps1`).

This report provides an honest accounting of the delivered capabilities, empirical metrics, architectural reconciliations, and deliberate scope deferrals:
1. **Defect Repairs:** All ten pre-fix defects (Defects 1–10) are formally repaired, verified against regression tests, and compared directly with saved before/after logs.
2. **Deterministic Benchmark:** The greedy scheduler vs. exact exhaustive oracle benchmark was rerun across 250 instances (5 random seeds $\times$ 50 instances). While achieving an empirical mean ratio of 0.9737, the scheduler exhibits discrete knapsack pathologies with a 5th percentile of 0.8270, an empirical minimum of 0.2143 (Instance 215), and a hand-derived counterexample ratio of 0.6667 (12/18). Exhaustive search was proven 100% order-invariant across all 250 shuffled DAG instances.
3. **Event Replanning & Simulation:** Implemented dynamic event replanning (`src/planning/replan.py`) handling assessment results, missed days, budget reductions, and shortened deadlines. Developed a transparent synthetic student simulator (`MatchedBKTGenerator`) with an `EvaluatorView` that maintains strict latent mastery isolation from planning and state code.
4. **Scope Exclusions & Cut Rules:** Live CAT question-bank item selection (M2), 2-up / 1-down exercise difficulty adaptation (M4), Half-Life Regression memory decay fitting (M5), and empirical ASSISTments/Junyi dataset training pipelines were deferred to Week 4 under declared project cut rules.
5. **Audit Independence Note:** In accordance with course evaluation rules, the audit tasks conducted during Week 3 were executed by the project team and AI tooling within the active development workspace. They do not constitute an independent external human review.

### Why Benchmark Aggregate Ratios Did Not Shift
The benchmark generation algorithm in `src/planning/benchmark.py` creates instances by adding directed prerequisite edges where $u < v$. In Week 2, activities happened to be presented to the oracle in natural topological order ($1..N$). Consequently, the order defect in Defect 3 was latent in the random benchmark instances, but was conclusively exposed when reversing input arrays (`[B (req A), A]`). In Week 3, a dedicated invariance suite (`tests/test_benchmark_invariance.py`) shuffled prerequisite definitions and activity lists for every single instance, confirming identical scores ($\Delta = 0.0$) across all 250 cases.

## 3. System Architecture & Components Delivered in Week 3

### 3.1 Bayesian Knowledge Tracing & pyBKT Parity (M1)
The core belief tracking model in `src/state/learner_state.py` was validated against `pyBKT 1.4.3` (`tests/test_m1_bkt_parity.py`). Numerical posterior parity holds within $|p_{\text{engine}} - p_{\text{pyBKT}}| < 10^{-4}$ across all canonical observation sequences. The conflict-sensitive window gate ($W=4$) was made dynamic, and the Weak mastery boundary was settled strictly at $p < 0.40$ (with $p = 0.40$ remaining in `Developing`).

### 3.2 Dynamic Event Replanning Engine (M6)
Implemented `src/planning/replan.py` supporting four discrete external events:
1. `assessment_result(node, correct)`: Updates concept mastery via BKT and reclassifies state. Unblocks dependent activities if passed (`Mastered`), or filters dependent activities with `PREREQUISITE_UNMET` and returns `HEURISTIC_NO_PLAN` if failed.
2. `missed_day(day)`: Records 0 minutes used on the missed day, rolls remaining work into subsequent days, and preserves previously completed nodes.
3. `changed_budget(new_budget)`: Evaluates atomic block feasibility. If any required activity exceeds `new_budget`, proves infeasibility immediately with `BLOCK_EXCEEDS_DAILY_BUDGET` and provides the exact actionable minimum budget fix.
4. `changed_deadline(new_deadline)`: Re-checks aggregate horizon capacity ($W_{\text{req}} \le D \cdot B$).

### 3.3 Transparent Synthetic Learner Simulator & EvaluatorView (M8)
Implemented `src/simulation/simulator.py` with two distinct architectural components:
- `EvaluatorView`: Holds the true underlying latent cognitive state ($L_c \in \{\text{True}, \text{False}\}$) and difficulty parameters.
- `MatchedBKTGenerator`: Emits observable binary responses ($Y \in \{0, 1\}$) using standard BKT slip ($p_S=0.10$), guess ($p_G=0.25$), and transition ($p_T=0.10$) probabilities.
- **Inaccessibility Invariant:** The latent state is strictly inaccessible to `src/planning` and `src/state`. Static analysis confirms zero imports of `EvaluatorView` or `simulation` across planning modules.

### 3.4 Configuration Provenance Engine (ADR-009 & Defect 10)
Implemented `src/provenance.py` providing:
- Canonical directory separation: runtime parameters in `config/`, evaluation and benchmark parameters in `experiments/`.
- `resolved_config_hash()`: Computes a deterministic SHA-256 hash across loaded configuration dictionaries.
- `write_manifest()`: Generates structured run manifests recording git commit SHA, timestamp, python version, host architecture, configuration hash, and generated output checksums.

### 3.5 End-to-End CLI Demonstration (`src/cli.py`)
Implemented a unified CLI entry point:
```bash
python -m src.cli demo --out evaluation/results/w3/demo --seed 20261012 --budget 10
```
The command executes eight end-to-end workflow steps across Novice and Intermediate learner profiles, demonstrates dynamic pass/fail replanning, validates missed days and budget reductions, writes 14 structured JSON artifacts, and verifies that all core artifacts are 100% byte-identical across repeated runs.

## 5. Scope Accounting: What Was NOT Done & Cut Rules Applied

To maintain strict scientific and project integrity, the team explicitly declares all components that were planned or discussed but not implemented in Week 3, alongside the governing cut rule from the project methodology:

### 1. Computerized Adaptive Testing Item Bank (Module M2)
- **What Was Not Done:** A live CAT item selection loop executing 2PL IRT maximum Fisher information queries against a discrete item bank.
- **Governing Cut Rule:** *Cut Rule 2 (Modular Cold-Start Prioritization).* The mathematical mapping linking diagnostic ability to initial concept mastery ($p_{c,0} = \operatorname{sigm}(\hat{\theta})$) was formally specified in `decisions/ADR-009.md` and `decisions/METHODOLOGY_RECORD.md`. The multi-skill item bank and Q-matrix mapping item IDs to curriculum DAG nodes were deferred to Week 4 to prioritize foundational planning correctness and defect repair.

### 2. Live External Dataset Training Pipeline (ASSISTments / Junyi)
- **What Was Not Done:** Automated download, ingestion, and offline BKT parameter fitting using raw student response logs from ASSISTments or Junyi Academy.
- **Governing Cut Rule:** *Cut Rule 1 (Synthetic-First Simulator Architecture).* As ratified in `decisions/METHODOLOGY_RECORD.md` (Table Item 1), the project adopted a simulator-first evaluation methodology. External real-world datasets provide offline validation baselines, but the core adaptive planning engine is benchmarked against calibrated synthetic cognitive simulators (`MatchedBKTGenerator`).

### 3. Dynamic Exercise Difficulty Stepping (Module M4)
- **What Was Not Done:** 2-Up / 1-Down runtime adjustment of item difficulty during exercise execution.
- **Governing Cut Rule:** *Cut Rule 3 (Planning-Over-Presentation).* Exercise difficulty boundaries ($[0.05, 0.95]$) and duration proxies are enforced at graph loading, but intraday exercise stepping was deferred until the assessment item bank is integrated.

### 4. Half-Life Regression Spaced Review Decay (Module M5)
- **What Was Not Done:** Calendar-timestamped recall probability decay modeling ($R_c = 2^{-\Delta t / H_c}$).
- **Governing Cut Rule:** *Cut Rule 4 (Topological Precedence Priority).* Review scheduling requires historical interaction timestamps that are absent from single-episode planning graphs. Prerequisite remediation and topological unblocking were prioritized over memory decay models.

## 7. Limitations and "Do NOT Claim" Boundaries

1. **No Universal Greedy Approximation Bound:** The greedy score-per-minute scheduler does not achieve a 95% worst-case approximation bound. The hand-derived counterexample ($\rho = 0.6667$) and benchmark minimum ($\rho = 0.2143$) prove suboptimality on discrete knapsack packing instances.
2. **Uncalibrated Belief Variance:** The Beta belief variance $\sigma^2$ is an uncalibrated heuristic confidence proxy driven by interaction count $n$, not an empirically fitted Bayesian posterior.
3. **Trace Checker Validation Edge Cases:** As identified during adversarial testing, `check_trace()` verifies schema field presence but does not currently type-check `concept_state` or `constraints` against `None`, nor does it reject negative remaining budgets.
4. **Graph Validator Edge NaN Pass-Through:** `validate_graph()` verifies finite numeric values for node `baseline_duration` and `base_difficulty`, but ignores NaN values in edge attributes (`importance`).
5. **Synthetic Evaluation Only:** All reported benchmarks and demo traces reflect synthetic curriculum DAGs and simulated BKT learners. No production student telemetry has been collected.
6. **Explicit "Do NOT Claim" List:**
   - Do NOT claim that CAT diagnostic item selection is live in the demo CLI.
   - Do NOT claim that the greedy scheduler guarantees $\ge 95\%$ optimality on every instance.
   - Do NOT claim that real ASSISTments or Junyi datasets are preprocessed or trained.
   - Do NOT claim that Week 3 underwent independent external audit.
