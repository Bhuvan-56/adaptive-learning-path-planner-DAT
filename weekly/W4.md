## 3. System Architecture & Components Delivered in Week 4

### 3.1 Adaptive Diagnostic & CAT Item Bank (M2)
Implemented `src/diagnostic/diagnostic.py` wrapping `catsim`:
- **Synthetic Item Bank:** 24 items synthesized in `data/processed/item_bank_synthetic.csv` fitted to synthetic data across difficulty $b \in [-2.0, 2.0]$ and discrimination $a \in [0.8, 1.5]$.
- **Declared Q-Matrix:** `data/processed/q_matrix_synthetic.csv` maps item IDs to curriculum concepts (A, B, C; D unprobed cold-start prior).
- **Stopping Rule:** Stops upon variance threshold $\text{Var}(\hat{\theta}) \le 0.15$ or a 10-item cap.
- **Mastery Mapping (ADR-009):** Maps estimated latent ability $\hat{\theta}$ to BKT prior mastery via logistic link: $p_{c,0} = \operatorname{sigm}(\hat{\theta}) = \frac{1}{1 + e^{-\hat{\theta}}}$. Unprobed concepts cold-start as uninformative $\operatorname{Beta}(1, 1)$ prior ($p=0.50, \sigma^2 \approx 0.0833 \to \text{Uncertain}$).

### 3.2 Dynamic Exercise Difficulty Adaptation (M4)
Implemented `src/planning/difficulty.py`:
- **2-Up / 1-Down Stepping Rule:** Two consecutive correct responses step difficulty up by $+0.2$; one incorrect response steps difficulty down by $-0.2$. Difficulty is bounded within $[-3.0, 3.0]$.
- **Execution Gate:** Enforces that exercise activities are gated strictly by prerequisite mastery evidence.

### 3.3 Spaced Review Scheduling & Remediation (M5)
Implemented `src/planning/review.py`:
- **Half-Life Memory Decay:** Evaluates recall probability $R_c = 2^{-\Delta t / H_c}$ parameterized by interaction timestamps and half-life prior $H_{\text{prior}} = 14.0$ days.
- **Review Trigger:** When $R_c < 0.85$, schedules a spaced review activity under reason code `REVIEW_DUE`, competing within the daily budget.
- **Prerequisite Remediation:** When an assessment activity fails repeatedly, triggers prerequisite review activities under reason code `REMEDIAL_PRIORITY`.

### 3.4 Dynamic Replanning & Trace Routing (M6, M7)
- Partitioned feasibility validation into `FEASIBLE`, `INFEASIBLE_PROVED`, and `HEURISTIC_NO_PLAN`.
- Implemented dual trace validation in `src/trace/checker.py`: feasible plans are verified via `check_trace()` (8 fields, day bounds $1..D$, non-negative budgets); infeasible plans route to `check_no_plan_trace()`.
- Multi-target plan requests are explicitly rejected with `MULTIPLE_TARGETS_UNSUPPORTED`.

### 3.5 Provenance & Profile Expansion Engine (ADR-009, M8)
- Updated `src/provenance.py` to incorporate complete curriculum graph structure, node durations, and edge attributes into canonical hashes with full floating-point precision.
- Implemented explicit profile-to-concept expansion via `data/curricula/demo_curriculum.groups.yaml` mapping coarse profile groups to DAG concept IDs.

### 3.6 Horizontal Slice Demonstration CLI (`src/cli.py`)
Implemented `python -m src.cli slice` generating 21 structured JSON artifacts in `evaluation/results/w4/slice/`:
- **Byte-Identical Replay:** Repeated runs with seed 20261024 emit 100% byte-identical artifacts.
- **Two Profiles:** Demonstrates Novice vs Intermediate profile initialization via CAT diagnostic.
- **Adversarial Matrix:** Validates budgets (5, 10, 15, 30 min), target changes, failed assessments, missed days, and shortened deadlines.

## 5. Scope Accounting: What Was NOT Done & Cut Rules Applied

To maintain strict scientific transparency, the team explicitly declares all components that were planned or discussed but not implemented in Week 4, alongside the governing cut rules:

### 1. Live External Dataset Training Pipeline (ASSISTments / Junyi)
- **What Was Not Done:** Automated download, ingestion, and parameter fitting using raw student response logs from ASSISTments or Junyi Academy.
- **Governing Cut Rule:** *Cut Rule 1 (Synthetic-First Simulator Architecture).* As ratified in `decisions/METHODOLOGY_RECORD.md` (Table Item 1), the project adopted a simulator-first evaluation methodology. Models and parameters are fitted to synthetic data; live production student telemetry was deferred.

### 2. Delayed Post-Intervention Retained-Recall Quiz (Milestone M8-d)
- **What Was Not Done:** Delayed retention testing $D$ days post-intervention scored strictly from latent state by evaluator under mismatched generative models.
- **Governing Cut Rule:** *Cut Rule 2 (Simulated Decay Precedence).* The student cognitive simulator currently implements stationary BKT state transitions without temporal memory forgetting. Measuring delayed retained recall is uninformative until forgetting dynamics are introduced into the generative simulator.

### 3. Dynamic Repack Repair Synthesis for Heuristic Infeasibility (Milestone M4-a)
- **What Was Not Done:** Automated combinatorial schedule synthesis to dynamically repair `HEURISTIC_NO_PLAN` packing failures.
- **Governing Cut Rule:** *Cut Rule 3 (Actionable Bounds Over Heuristic Synthesis).* Exact necessary-and-sufficient repairs are provided for single-block exceedances ($> B$) and horizon capacity overruns ($> DB$). Dynamic repack synthesis on NP-hard knapsack packing failures was bounded to returning `HEURISTIC_NO_PLAN` with structured nested explanations.

### 4. Multi-Target Simultaneous Path Planning
- **What Was Not Done:** Simultaneous scheduling for multiple disjoint target competencies.
- **Governing Cut Rule:** *Cut Rule 4 (Single-Target Coherence).* The engine explicitly bounds planning requests to a single target competency; requests specifying multiple targets are rejected with `MULTIPLE_TARGETS_UNSUPPORTED`.

### 5. Online Multi-Armed Bandit Policy (ADR-008)
- **What Was Not Done:** Runtime exploration/exploitation balancing via contextual bandits.
- **Governing Cut Rule:** *Cut Rule 5 (Safety Guardrail Priority).* Retained as a proposed architectural extension. Core planning is driven by deterministic topological scoring and adaptive difficulty ladders.
